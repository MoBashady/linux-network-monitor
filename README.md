# Linux Network Monitoring & Process Attribution System

A Linux network monitoring application built with C++, Python, and PyQt5 that captures network packets, identifies the processes and users associated with network connections, logs packet activity, and visualizes the results through a desktop dashboard.

The project was developed as part of an Operating Systems course and explores Linux networking, the `/proc` filesystem, process management, raw sockets, and real-time monitoring.

## Features

- Captures network traffic using Linux `AF_PACKET` raw sockets
- Parses Ethernet and IPv4 packets
- Identifies TCP and UDP traffic
- Extracts source and destination IP addresses and ports
- Maps network connections to Linux socket inodes
- Maps socket inodes to process IDs using `/proc/<pid>/fd`
- Retrieves process names and owning users
- Logs captured traffic to JSONL
- Displays live network activity through a PyQt5 GUI
- Tracks packet and byte statistics
- Displays TCP, UDP, and other protocol percentages
- Supports filtering by process, user, and protocol
- Provides a raw JSON traffic view

## Packet Capture

The C++ backend creates a raw socket using:

```cpp
socket(AF_PACKET, SOCK_RAW, htons(ETH_P_ALL))
```

Captured Ethernet frames are inspected to determine whether they contain IPv4 traffic.

For TCP and UDP packets, the monitor extracts:

- Source IP
- Destination IP
- Source port
- Destination port
- Protocol
- Packet size

## Process Attribution

One of the main goals of the project is to associate network traffic with the process responsible for it.

The monitor first searches Linux networking information in:

```text
/proc/net/tcp
/proc/net/tcp6
/proc/net/udp
/proc/net/udp6
```

The matching socket inode is then compared against symbolic links inside:

```text
/proc/<pid>/fd/
```

When a matching socket is found, the application identifies the corresponding PID.

The process name is retrieved from:

```text
/proc/<pid>/comm
```

and the owning user is determined using information from:

```text
/proc/<pid>/status
```

## Traffic Logging

The integrated C++ monitor stores captured traffic in:

```text
network_log.jsonl
```

Each line contains structured information such as:

```json
{
  "timestamp": "14:32:10",
  "process": "firefox",
  "pid": 4321,
  "user": "user",
  "bytes_sent": 1500,
  "bytes_received": 0,
  "protocol": "TCP",
  "remote_ip": "192.168.1.10"
}
```

The PyQt5 interface reads this file while the backend is running and updates the dashboard.

## GUI

The Python interface contains three main views.

### Dashboard

Displays:

- Monitoring status
- Total packet count
- Total captured bytes
- Average packet size
- TCP packet count and percentage
- UDP packet count and percentage
- Other protocol statistics
- Real-time traffic graph

### Processes

Displays captured traffic in a sortable table containing:

- Timestamp
- Process
- PID
- User
- Sent KB
- Received KB
- Protocol
- Remote IP

Traffic can be filtered by:

- Process
- User
- Protocol
- All fields

### Raw JSON

Displays the raw JSON records generated by the monitoring backend.

## Traffic Statistics

- Total bytes
- TCP packets
- UDP packets
- Other packets
- TCP bytes
- UDP bytes
- Other bytes
- Average packet size
- Protocol percentages

## Requirements

This project is designed for **Linux** because it relies on:

- `AF_PACKET`
- Linux raw sockets
- `/proc/net`
- `/proc/<pid>`

Python dependencies can be installed with:

```bash
pip install -r requirements.txt
```

## Building the Backend

Compile the integrated C++ monitor:

```bash
g++ -std=c++17 integration.cpp -o integration
```

## Running the Project

Raw packet capture normally requires elevated privileges on Linux.

Start the monitoring backend:

```bash
sudo ./integration
```

The backend will begin capturing packets and writing records to:

```text
network_log.jsonl
```

In another terminal, start the GUI:

```bash
python3 network_gui.py
```

Click **Start Monitoring** in the GUI to begin reading and displaying the captured traffic.

## Current Limitations

- The application is Linux-specific.
- Raw socket access normally requires root privileges or the appropriate network capability.
- Process attribution depends on whether the corresponding socket can be found in `/proc`.
- Some packets may therefore appear with an unknown process or user.
- The current integrated logger records each captured packet under `bytes_sent`, while `bytes_received` is currently set to zero.
